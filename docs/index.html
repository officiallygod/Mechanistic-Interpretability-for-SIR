Explainable Object Sets for Robot Policies

Investigating whether an untouched, end-to-end vision policy implicitly forms a sparse, latent kept set of task-relevant objects using Sparse Autoencoders (SAEs).

The Guiding Research Question

"Does a robot manipulation policy trained without any explicit object selection form an implicit, latent 'kept set' of objects inside its intermediate representations?"

While prior methods like SIR (CVPR 2026) explicitly prune a scene graph inside the policy, the companion ICLR 2027 paper revealed that explicit subset bottlenecks often suffer from subtle leakage paths (e.g. graph-level normalizations and survivor score scaling) and struggle to simultaneously satisfy Discovery, Removal, and Consequence. In Topic 2, we take an unconstrained vision policy (ResNet-18 + MDT diffusion action generator) and use mechanistic interpretability to determine whether object modularity emerges naturally.

Methodology & Step-by-Step Pipeline

How we extract, ground, and test implicit object sets without modifying policy weights.

1

Activation Tapping (layer4)

During policy execution, we register forward hooks at ResNet-18 layer4. Rather than pooling across space, we extract the raw $7 \times 7$ grid of 512-dimensional vectors (49 spatial tokens), each possessing an isolated receptive field over the camera view.

2

Overcomplete Sparse Autoencoder

We train an SAE to reconstruct the 512-d activations using an expanded feature dictionary ($M = 4096$, $8\times$ expansion). Enforcing Top-K sparsity ($K \approx 32$) decomposes polysemantic neuron activations into distinct, monosemantic feature directions.

3

Spatial Grounding to Simulator Boxes

Active SAE features are mapped across the $7 \times 7$ spatial grid into 2D heatmaps. By computing Intersection-over-Union (IoU) against simulator 2D/3D bounding boxes from RoboCasa/CALVIN, features are semantically labeled to specific objects.

4

Latent Kept Set ($K_{latent}$)

At any timestep $t$, the objects whose grounded SAE features are active constitute the policy's Latent Kept Set $K_{latent}$. This provides a dynamic, human-interpretable readout of what the policy is internally attending to.

The Three Foundational Verification Tests

Rigorous tests established in the companion ICLR 2027 paper applied to the latent kept set.

1. Discovery Condition (D-C)

Measured

Requirement: The selection must be discovered by the model itself rather than imposed by ground-truth supervisory lists.

Our Test: Because the baseline ResNet-18 is trained end-to-end on image pixels without any object bounding-box loss or node annotations, it passes the permutation test by construction. We measure whether the emergent SAE features spontaneously identify task-relevant objects above chance level.

2. Removal Condition (R-C)

Causal Ablation

Requirement: Excluded objects must be strictly absent from the downstream computation, ensuring the action depends only on $K_{latent}$.

Our Test: We perform causal feature ablation during policy rollouts: for any object outside $K_{latent}$, we clamp its corresponding SAE feature activations to zero ($f_j = 0$), decode the reconstructed activation vector $\hat{x}$, and inject it back into the MDT action generator. We record whether the generated action remains completely invariant.

3. Consequence Condition (C-C)

Closed-Loop Success

Requirement: The selection must matter beyond a matched random subset of the same size (sufficiency + selectivity).

Our Test: We evaluate full rollout success rates when ablating task-relevant features vs. ablating random feature sets of identical sparsity. If ablating $K_{latent}$ features drops success to the blind policy baseline while ablating irrelevant features preserves task completion, the explanation is causally validated.
