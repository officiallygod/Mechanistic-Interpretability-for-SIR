The Guiding Research Question

"Train a sparse autoencoder on the activations of an image policy that has no object selection. Start with the ResNet-18 7×7 feature map before pooling. Label each feature by where it fires (activation map vs. object boxes from the simulator). The objects whose features are active at a step form a 'latent kept set'. Need to see if we take a whole object or only parts of objects (pixel level or object level). Direction: does a policy without explicit selection form an object set internally? Test the latent kept set with Discovery, Removal and Consequence, by switching features off during rollouts, and compare it with SIR's explicit kept set."
Core Direction

Does a vision policy without explicit subset selection form an implicit object set internally? We test this latent kept set under Discovery, Removal, and Consequence by switching features off during rollouts.

Granularity: Whole vs Part

Do active SAE features capture entire objects (object-level) or isolate localized functional affordances (e.g. drawer handle, mug rim, gripper fingers)? We evaluate pixel-level vs part-level vs whole-object bounds.

Methodology & Step-by-Step Pipeline

How we extract, ground, and test implicit object sets without modifying policy weights.

1

Activation Tapping (layer4)

During policy execution, we register forward hooks at ResNet-18 layer4. Rather than pooling across space, we extract the raw $7 \times 7$ grid of 512-dimensional vectors (49 spatial tokens), each possessing an isolated receptive field over the camera view.

2

Overcomplete Sparse Autoencoder

We train an SAE to reconstruct the 512-d activations using an expanded feature dictionary ($M = 4096$, $8\times$ expansion). Enforcing Top-K sparsity ($K \approx 32$) decomposes polysemantic neuron activations into distinct, monosemantic feature directions.

3

Spatial Grounding to Simulator Boxes

Active SAE features are mapped across the $7 \times 7$ spatial grid into 2D heatmaps. By computing Intersection-over-Union (IoU) against simulator 2D/3D bounding boxes from RoboCasa/CALVIN, features are semantically labeled to specific objects.

4

Latent Kept Set ($K_{\text{latent}}$)

At any timestep $t$, the objects whose grounded SAE features are active constitute the policy's Latent Kept Set $K_{\text{latent}}$. This provides a dynamic, human-interpretable readout of what the policy is internally attending to.

The Three Foundational Verification Tests

Rigorous tests established in the companion ICLR 2027 paper applied to the latent kept set.

1. Discovery Condition (D-C)

Measured

Requirement: The selection must be discovered by the model itself rather than imposed by ground-truth supervisory lists.

Our Test: Because the baseline ResNet-18 is trained end-to-end on image pixels without any object bounding-box loss or node annotations, it passes the permutation test by construction. We measure whether the emergent SAE features spontaneously identify task-relevant objects above chance level.

2. Removal Condition (R-C)

Causal Ablation

Requirement: Excluded objects must be strictly absent from the downstream computation, ensuring the action depends only on $K_{\text{latent}}$.

Our Test: We perform causal feature ablation during policy rollouts: for any object outside $K_{\text{latent}}$, we clamp its corresponding SAE feature activations to zero ($f_j = 0$), decode the reconstructed activation vector $\hat{x}$, and inject it back into the MDT action generator. We record whether the generated action remains completely invariant ($\Delta a \approx 0$).

3. Consequence Condition (C-C)

Closed-Loop Success

Requirement: The selection must matter beyond a matched random subset of the same size (sufficiency + selectivity).

Our Test: We evaluate full rollout success rates when ablating task-relevant features vs. ablating random feature sets of identical sparsity. If ablating $K_{\text{latent}}$ features drops success to the blind policy baseline while ablating irrelevant features preserves task completion, the explanation is causally validated.
